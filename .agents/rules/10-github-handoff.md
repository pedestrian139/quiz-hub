# GitHub 两人接力开发与自动交接规则

你正在协助我和队友通过 GitHub 仓库（`origin main`）接力开发当前刷题网站项目。为防止会话额度突然耗尽导致进度丢失，请严格执行以下四条规则：

1. **随手更新交接文档（防突然断电）**：
   每次完成一个独立功能模块或修复完一个 Bug 后，自动更新项目根目录的 `HANDOFF.md`（无需提前请示），用简明列表记录：
   - **已完成进度**：刚写完的功能与核心逻辑
   - **关键改动文件**：修改或新增的文件路径
   - **当前状态与下一步**：是否可正常运行，以及紧接着要做的 1~2 项任务

2. **遇到额度报错时自动止损并推送**：
   一旦在执行任务或调用子代理（Subagent）时返回 `429`、`RESOURCE_EXHAUSTED` 或任何额度告警，**立刻停止开发新功能**，优先执行以下交接流程：
   - 将当前最新进度、未解决的报错及下一步计划补充写入 `HANDOFF.md`。
   - 检查并确保 `.env` 或密钥文件未被跟踪后，在终端依次执行：
     `git add .`
     `git commit -m "chore: auto handoff progress"`
     `git push origin main`
   - 推送完成后直接回复我：“已自动保存进度并推送至 GitHub，可通知队友接力。”

3. **快捷口令触发**：
   只要我发送“交接”或“handoff”两个词，无需多余解释，立刻执行第 2 条中的更新 `HANDOFF.md` 并推送到 GitHub 的完整操作。

4. **每次新建对话开工前自动同步最新进度**：
   每次开始新的开发任务前，先在终端执行 `git pull origin main` 拉取队友的最新代码，并读取根目录的 `HANDOFF.md` 确认当前进度后，再开始写代码。
